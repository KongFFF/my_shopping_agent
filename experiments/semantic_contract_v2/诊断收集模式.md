## 新入口

新增 `tools/collect_semantic_diagnostics.py`。没有修改原提取器、prompt、schema、归一化规则、校验规则或奖励规则。

- 在独立目录保存原运行快照和全部 13 条历史尝试，原目录保持原样。
- 已收到模型回答的题，无论程序校验成功或失败，都不重复调用。因此起点为已收集 9/50，只补剩余 41 题。
- 新题仍使用原入口的两次尝试及错误反馈机制。记录失败并继续下一题，不把失败改成通过。
- 鉴权/配置类 HTTP 4xx（429 除外）立即停止；连续三题没有收到有效 API 响应包时停止。HTTP 200 的模型回答即使内部 JSON 不合法，也保留作诊断样本。
- 可中断续跑；相同命令会跳过已有模型回答的题。若第一次回答后中断，该题恢复时也会跳过，未必补齐第二次尝试。
- 源运行、采集入口及配置均校验哈希。运行期间不要再用旧命令向源目录追加记录，也不要改代码或输入快照。

## 结果解读

采集目录：`outputs/semantic_school_contract_v2_50_v2_collect`。

| 文件或字段 | 含义 |
| --- | --- |
| `seed_attempts.jsonl` | 原始 13 条历史记录的逐字节副本 |
| `per_task/<ID>/attempts.jsonl` | 该题新增调用的原始记录 |
| `attempts.jsonl` | 历史及新记录的汇总；原始顺序在各自日志内保留 |
| `collected_failures.jsonl` | 已有模型回答但尚未通过校验的题及错误 |
| `responses.normalized.jsonl` | 仅包含通过当前程序校验的归一化结果 |
| `report.json: collection_complete` | 是否 50 道题都有模型回答，用于判断诊断样本是否收齐 |
| `report.json: complete` | 是否全部通过程序校验；仍不代表人工语义审阅通过 |
| `report.json: new_api_attempts` | 采集入口累计新增调用数，不包含原来的 13 次 |
| `report.json: usage_all_attempts` | 包含原运行历史的 token 总计，不能当成此次新增消耗 |

`collection_complete: true` 而 `complete: false` 是允许的诊断结果。此时退出码可为 0，表示收集结束，不表示这些数据可直接用于训练或评分。下一步审阅通过与失败的全部 50 题，汇总共性问题，再决定协议和提示词的修订。
