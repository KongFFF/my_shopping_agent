# 历史购买自动核验独立测试 v1

本实验不启动GPU、不改原1000题、19题暂缓名单、训练奖励公式、训练包或真实训练入口。

- 数据：先取v3、v4的旧训练采样作为缓存准备部分；以v5新顺序采样为后续测试部分。仅取generation_batch，排除optimizer_step里重复拷贝的轨迹。
- 评分：以当前冻结契约和同一商品快照重新计算规则基线，不把旧gold/native标签视为语义真值。规则已知pass/fail保持；自动模型只补非预算unknown。预算保留确定性价格核验。未知仍按既定固定分母和零证据分处理。
- 提示词：system_prompt.txt。输出schema由tools/purchase_judge_benchmark.py的output_schema固定，并随数据快照保存。模型不能输出最终奖励。
- 证据：只给公开文字及所选规格；不提供标准ASIN、目标选项、未选规格、reviews、商品原始is_selected字段、规则判分或人工参考答案。逐项核查id、状态、原因、指针与完整原文标量。引用存在不等于语义推理正确。
- 缓存：绑定完整需求契约、商品快照、实际选项、提示词/schema、规则与奖励程序版本；API输出另绑定模型、端点和配置。不按裸ASIN缓存最终奖励。
- 参考：由助手在查看模型判断前阅读公开资料建立，包含244项判断、31个购买组合、4个排序对照。是分层定向样本，不是1000题随机准确率，也不是新增训练签收。244项只有6个明确反例，无法可靠估计罕见误放行率。
- 并发：按真实历史生成批次设置屏障，最多4个请求并发，同批相同请求合并等待一个future；后续批次才计为已就绪缓存命中。该测试实测的是客户端批次等待，不是GPU空转时间，也没有验证GPU上的异步重叠。
- 失败：每次运行每项最多2次尝试；401/403/402/404停止继续调度。失败不当成unknown、不给新训练分、不回退旧奖励。断点续跑会重试仍失败的项，所有尝试均留日志。
- 验收：质量、误放行、排序、调用可靠性、整批尾延迟分别报告。工程门槛是本次建议，不改变用户确认的奖励契约。全部质量门槛通过也只构成进一步测实现开销的候选，不能自动放行正式GRPO。

密钥只从临时环境变量或显式--env-file读取。不得提交.env文件。默认HTTPS；学校HTTP仅显式--allow-school-http允许原有白名单地址。日志不记录Authorization头或网关错误正文。
