## 固定字段

六个顶层语义维度始终存在，没有要求时使用空数组：

| 机器字段 | 含义 | 固定子类型 |
| --- | --- | --- |
| category | 商品类别 | product_category |
| budget | 预算 | 总价、单价、定金、尾款、加工费、运费 |
| functions | 功能与用途 | 功能、用途、适用对象、使用环境 |
| specifications | 规格与购买条件 | 数量、套餐、组成、颜色、尺码、尺寸、材质、容量、净含量、兼容性、商家、配送、保修 |
| brand | 品牌 | brand |
| model | 型号 | product_model、version |

每条需求有唯一ID、固定子类型、required/preference/uncertain性质、比较操作、结构化期望、原文字符位置与引用、审阅状态。未覆盖/冲突的内容进入pending_mentions，不允许LLM自由新增评分维度。

schema拒绝额外字段、隐藏答案字段、类型错误和非法单位；程序进一步检查引用必须与原始query逐字对应、ID唯一、数值有限、区间有效、操作与值类型相容。正式评分前必须提供独立原query核对，全部条目获批且无uncertain/pending_mentions。

**以上是结构与来源校验，不证明语义提取正确、完整、去重正确或SKU事实正确。** 同一事实的不同表述是否重复，需要审阅解决。approved只可由审阅流程确认，不应相信LLM自行填写的批准状态。

## 已批准的奖励政策

1. 必需项全部满足即语义成功；偏好调节成功后的奖励。无偏好要求时成功取1。
2. 必需类别不满足、必需预算不满足直接判-0.85。其他必需项失配保留部分分。
3. ASIN不影响新语义奖励，等价商品同等评分。旧ASIN严格成功率另行保留，不能与新语义成功率混用。
4. 成功奖励0.55～1；部分失败-0.30～0.25。
5. 六维等权，维度内部已审阅且去重的需求等权。无相应性质需求的维度不参与分母，不是自动补满分。

设M为仅针对必需项的满足度，P为仅针对偏好的满足度：分别先在每个活跃维度内取均值，再对活跃维度等权平均。必需项是否全满足单独逐项检查，其他维度高分不能把一个未满足的必需项抵消。

| 情况 | 原型结果 |
| --- | --- |
| 已确认必需类别/预算失败 | -0.85，有效失败 |
| 其他证据无法核验 | 无法确定语义成功，reward_valid=false；不能忽略后给满分 |
| 必需项全满足，无偏好 | 1，语义成功 |
| 必需项全满足，有偏好 | 0.55 + 0.45×P，语义成功 |
| 其他必需项有失败 | -0.30 + 0.55×M，部分失败 |

偏好在必需项未满足时不影响首版部分分，避免仅改善偏好掩盖核心要求失配。已确认类别/预算失败足以确定失败档，即使另有未知偏好也不把该有效负例过滤。单项核验目前为pass/fail/unknown，尚无每项连续相似度。

## 当前实现边界

- `requirements.schema.json`：固定结构。
- `example.synthetic.json`：合成示例，ID0只是示例，不是对真实task_id=0的标注；状态pending。
- `tools/semantic_contract_v1.py`：结构、证据位置与审阅状态校验。
- `tools/semantic_reward_v1.py`：对外部已核验的逐项pass/fail/unknown结果做聚合。
- `reward_policy.json`：已选定政策与数值。
- `extraction_prompt.md`：离线提取约束草案。

**原型尚未自动核验商品/所选SKU、真实购买终局、数量/套餐组成或商家事实，也没有把新结果转换为veRL adapter字段。** 不能把手工提供的逐项比较结果称为完整自动奖励系统；不能把semantic_success直接改名为旧gold_purchase。

购买保护、循环、步数耗尽和基础设施异常的运行时行为继续使用v1.1。接入新评分时必须专门处理它们，不能在没有实际购买时仅凭需求满足表报告成功。
