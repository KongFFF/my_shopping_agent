# 离线提取约束草案

输入仅包含原始用户Query和已公布的需求schema。输出严格遵守schema的JSON。

- 原Query逐字保留。每条需求必须提供原文中真实存在的字符区间和引用。
- 六个维度始终存在；未提出的要求填空数组，不补充常识偏好。
- 只提取用户表达的需求，不从gold商品、目标规格或其他标注倒推用户需求。
- 明确要求标required，明确偏好标preference；强弱或含义不能确定时标uncertain/记录pending_mentions。
- 所有review_status必须为pending；模型不能批准自己的提取。
- 数量、购买数量、赠送数量、套餐组成分开表示；数字不能仅因为出现在Query中就当型号。
- 商家、品牌、型号分别判断，不能仅凭同一文本共现混成一个概念。
- 单位转换和预算近似须符合固定解释政策。不能擅自把“左右”变成精确上限，无法可靠表示时保持待审。
- 不把同一个要求在功能与规格中重复计数；无法确定是否重复时交审阅。
- 不生成reward、权重、目标ASIN、正确SKU或训练建议。
- 合成示例仅演示结构，不能把示例内容抄进其他任务。

程序校验仅能验证部分结构和引用一致性。人工仍需检查漏项、错误推断、强弱分类、单位/数量语义和重复计数。
