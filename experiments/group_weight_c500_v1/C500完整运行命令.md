# C500完整运行命令

2026-11-23。先执行第1段无卡准备；仅显示C500_PREPARED=true且无报错后再开有卡执行第2段。程序预算仅记账，由用户管理。当前尚未执行云端验收或训练。

## 1. 无卡拉取、CPU验收及准备

以下整段直接粘贴到终端。严格模式只在子bash内生效，失败不会退出你的交互终端。使用唯一新克隆，不覆盖已有目录；原有B不需切分支。

```bash
cd /root/autodl-tmp/work/my_shopping_agent
bash <<'BASH'
set -euo pipefail
ROOT=/root/autodl-tmp/work/my_shopping_agent
cd "$ROOT"
mkdir -p "$ROOT/outputs"
LOG="$ROOT/outputs/c500_prepare_$(date -u +%Y%m%dT%H%M%SZ)_$RANDOM.log"
exec > >(tee -a "$LOG") 2>&1
trap 'rc=$?; printf "PREPARE_EXIT_CODE=%s\nLOG=%s\n" "$rc" "$LOG"; if [[ "$rc" != 0 ]]; then echo "准备失败，保留日志，不要启动训练。"; fi' EXIT
[[ ! -e "$ROOT/outputs/c500_active_run.txt" ]] || { echo 'C500已准备过，请使用status/return，勿重做prepare。'; exit 1; }
CODE=$(mktemp -d "$ROOT/outputs/c500-code-XXXXXX")
printf 'CODE=%s\n' "$CODE"
git -c http.version=HTTP/1.1 clone --depth 1 --single-branch --branch codex/c500-gamma4 "$(git remote get-url origin)" "$CODE"
bash "$CODE/tools/c500_commands.sh" prepare
BASH
```

原环境CPU检查包含原veRL源文件、C方法测试、B同配置核对及基线身份哈希；不会加载模型、启动环境或训练。CPU测试收据在新CODE/outputs/c500_native_cpu.json；即使通过，也不能代替真实GPU/FSDP恢复验收。

## 2. 开有卡后启动0→350→500

```bash
cd /root/autodl-tmp/work/my_shopping_agent
bash <<'BASH'
set -euo pipefail
ROOT=/root/autodl-tmp/work/my_shopping_agent
PY="$ROOT/upstream/shopping-grpo-longhorizon/.venv/bin/python"
IFS= read -r RUN < "$ROOT/outputs/c500_active_run.txt"
CODE=$("$PY" -c 'import json,sys; print(json.load(open(sys.argv[1]))["repo"])' "$RUN/run.json")
bash "$CODE/tools/c500_commands.sh" run
BASH
```

后台启动，输出SUPERVISOR_PID及LOG。两阶段自动衔接，350正常停止后自动恢复至500。启动检查沿用B的原硬件条件：GPU空闲至少90GiB、CPU配额至少110GiB；数据盘至少60GiB空闲。请通过第3段核实实际启动与进展。
