# B500实际运行命令

2026-11-18。本轮覆盖独立准备、GPU训练0→350→500、状态检查和轻量证据Git回传。方法协议与已通过AutoDL CPU验收的核心实现不变。实际GPU资源和首步运行仍由执行时检查验收，不能以CPU测试替代。

## 1. 无卡准备（完整复制）

本步骤不启动环境、Ray、GPU或训练。新代码克隆使用唯一目录；实际B输出固定为`/root/autodl-tmp/work/my_shopping_agent/outputs/runs/b500_group_weight_v1`。目录已存在会停止，不覆盖或删除。不要source脚本，始终用下面的bash子进程方式。

```bash
if (
  cd /root/autodl-tmp/work/my_shopping_agent &&
  mkdir -p outputs &&
  git -c http.version=HTTP/1.1 fetch origin codex/b500-live-run-v1 &&
  git show FETCH_HEAD:tools/b500_commands.sh > outputs/b500_commands_live_v1.sh &&
  bash outputs/b500_commands_live_v1.sh prepare
); then
  printf '准备完成，尚未训练。确认 PREPARED 后再执行第2步。\n'
else
  printf '准备失败，请保留日志；不要执行第2步，不要删除已有目录。\n'
fi
```

准备会复核当前SFT/数据/基线源码身份，绑定云端CPU通过的实现，生成phase350/phase500两份配置与run.json，不新建或加载真实模型。两段配置的目标都保持500步，15步warmup不因350边界缩短；第二段从350恢复并关闭重复step0验证。固定Actor更新8轨迹，模型输入与原配方一致。

## 2. 开卡后启动后台训练

先确认第1步成功。使用原训练同等级单GPU资源；脚本要求空闲显存≥90GiB、CPU配额≥110GiB，并根据历史完整checkpoint大小（缺失时采用保守SFT估算）检查最多13个跨恢复保存点及导出余量。max_keep配置仍为原10，但跨进程恢复可能重置内存中的保留队列，磁盘采用13份保守预留，不主动删除旧文件。条件不足会停止，不自动降低batch、改模型或更换训练配方。

```bash
if bash /root/autodl-tmp/work/my_shopping_agent/outputs/b500_commands_live_v1.sh run; then
  printf '后台启动请求已提交，请立即执行第3步检查实际启动结果。\n'
else
  printf '启动请求失败，请保留日志并执行status；不要反复run。\n'
fi
```

PID只说明后台请求已提交，不能证明已开始训练。监督日志为`outputs/runs/b500_group_weight_v1/supervisor.log`，程序通过nohup运行，当前终端断开不主动中止监督进程。不会自动关机。

自动顺序：原运行预检→独立环境5727端口→8个槽位reset/release→第一段训练→第1步完整checkpoint/有限非零梯度/LR/B有效token指标验收→继续至350→350完整checkpoint与诊断落盘→清理本段自有Ray进程→从350完整恢复→训练至500→核对诊断唯一连续1—500→结束自有服务与训练进程。

## 3. 查看状态与日志

```bash
if bash /root/autodl-tmp/work/my_shopping_agent/outputs/b500_commands_live_v1.sh status; then
  printf '状态读取完成。\n'
else
  printf '状态读取失败，请保留输出。\n'
fi
```

主要状态文件：

- `accepted_step_1.json`：真实首步检查点、lr和非零有限梯度已验收；失败不自动继续。
- `phase350_complete.json`：350检查点及该步诊断完整，已达到预设恢复边界。
- `accepted_step_500.json`：500保存与指标检查通过。
- **`training_complete.json`：完整有效更新链1—500通过**；这才是本轮训练完成标记。
- `stopped.json`或`budget_truncated.json`：停止/截断，不能叫B500完成。保留目录，不直接重复run、prepare或自行改配置。

训练日志分别为`train_to_350.log`、`train_to_500.log`，权重/token记录为`weights.jsonl`，原生轨迹诊断为`training_diagnostics.jsonl`。需要实时查看时，在另一个终端执行：

```bash
tail -f /root/autodl-tmp/work/my_shopping_agent/outputs/runs/b500_group_weight_v1/train_to_350.log
```

Ctrl+C只退出tail查看，不终止后台训练。恢复后改看`train_to_500.log`。

## 4. 训练结束或失败后，Git回传

监督进程仍运行时回传会被文件锁阻止。正常完成与异常停止都可回传，模型权重不上传：

```bash
if bash /root/autodl-tmp/work/my_shopping_agent/outputs/b500_commands_live_v1.sh return; then
  printf '回传完成，请发送 RETURN_BRANCH 和 RETURN_COMMIT。\n'
else
  printf '回传失败；保留全部目录和日志。若训练仍在运行，请等待结束。\n'
fi
```

回传包括监督/训练/环境日志、生成预算、首步/350/500收据、两段冻结配置、原生轨迹和B权重记录；不包含模型tensor、SFT、.venv或凭据。网络失败保留新克隆与commit，可只重试push或重新运行return，不会重训。

## 成本、停止和后续评测

- 在每个生成批次前预留全部训练轨迹，24000条上限包含有效、无效、丢弃、跳过及失败尝试；无法放下完整下一批就停止。计数跨350恢复保存，不清零。
- 验证单列物理生成数。原Dev逻辑50题会按8个worker补齐批次，因此物理生成多于50；记录实际开销，不能只报550个逻辑Dev回合。本轮物理验证上限2400条，正常11次验证约2200条。
- 20小时时钟从第2步后台监督开始计，包括GPU资源预检、环境启动和训练内验证；生成前保留2分钟，监督在硬截止前30秒停止自有进程。卡上空闲等待也不能当免费；脚本不执行AutoDL关机。完成或失败后及时回传并关闭有卡实例，回传可在无卡模式进行。
- 达到预算时保留最近安全checkpoint，报告截断，不自动放宽预算或换seed。生成返回的Actor mask token另记；未从原接口取得的跨回合累计prompt token记录为未知，不能用Actor上下文长度冒充全部API输入成本。
- 本轮`training_complete.json`明确标注独立Dev尚未执行、Final未执行。500成功证据验收后继续同一冻结协议的模型导出与独立Dev50；不把训练内Dev当独立成绩，不自动跑Final或续800。

运行控制新增在独立`b500_run_control.py`中；核心B损失/CPU验收清单保持原哈希。控制层及命令在launch_manifest.json单独绑定。CPU控制测试覆盖预算预留/拒绝、完整checkpoint、350边界、精确自有进程判断、配置500目标与恢复日程；真实GPU首步仍须执行时验收。
