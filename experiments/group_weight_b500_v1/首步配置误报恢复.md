# B500首步配置误报与恢复

2026-11-18。适用于0/500时出现 `B500 configuration differs from supported frozen Actor contract` 的这一笔失败；不是通用重启工具。保留原目录，不重复旧prepare/run，不改共享site-packages。

## 原因及改动边界

历史A的组合配置同时包含 `actor.policy_loss.loss_mode=vanilla` 和 `algorithm.rollout_correction.bypass_mode=true/loss_type=ppo_clip`。锁定的veRL trainer在调用Actor更新前执行 `apply_bypass_mode`，把Actor模式改为 `bypass_mode` 并挂入同一rollout_correction配置；其损失函数按ppo_clip分派回原vanilla PPO。旧B检查器只接受转换前的vanilla，因而在调用真实Actor更新前误报。

修复仅允许这条已冻结转换：算法及Actor活动配置都必须保持ppo_clip、IS/RS关闭及原阈值。其他差异逐字段报错，不禁用bypass、不跳过检查、不改变奖励/采样/组权重。研究协议SHA256仍为 `390201e5e1a75b4be136ec2e0a89f09f38855b19f3a6c372bb0f64d5c122c2e8`。

旧CPU验收只覆盖转换前配置，没有覆盖此运行时变更，不能作为修复版的验收。新增测试使用原wheel的真实apply_bypass_mode和PPO分派函数，检查配置接受、非法REINFORCE/IS/RS拒绝、损失和梯度一致。真实GPU首步仍需accepted_step_1验收。
