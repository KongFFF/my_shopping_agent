# r4：预算政策归一化与待审接口（2026-11-03）

本轮不调用API。使用既有r3运行保存的96次回答做离线验证，原始日志、原报告、r3及其热修复均保留。原训练1000题及固定50题的ID/query不变，六个语义维度和已确认奖励区间不变。本包未接入训练，也未批准任何提取合同。

## 本轮实现

1. `semantic_policy_v4.py`把既定预算政策落到程序：金额和计价基准能被原文核验后，从本条原文恢复required/preference/uncertain。近似金额不自动降为不确定；明确最好保留偏好，希望及真实条件继续待审，不能把其他分句的偏好扩散到预算。
2. 仅移除**同一预算原文范围内、纯货币语句且已被政策解决**的undefined_tolerance或ambiguous_strength。其他歧义原因、范围过宽的待审、主观质量、非预算尺寸容差和未知单位继续保留。所有变更记入audit，review_status不改成approved。独立校验也拦截手工重新塞入的错误预算强弱/待审。
3. 需求项evidence仍是数组；pending_mentions的标准输出是单个证据对象。raw schema兼容单元素数组并记录解包审计；内部始终只有单对象。多段待审数组不自动合并/删除，而是要求一条真实连续上下文，或确实独立的多条待审。新增容器类型检查，避免在schema前再次发生list.get异常。
4. 对“明确用途只放pending”和“背景误作待审”增加检查，不自动推断缺失需求，也不自动删除潜在真实歧义。需要修订的题继续留在清单中。
5. 新增独立`--profile semantic-v2-r4`，50/1000模式均可本地准备；运行快照和复用检查包含新增预算政策模块。`check_semantic_contract_v2.py`通过版本分发兼容r4。

新增边界测试还发现并修复：“一定要”或“一共”中的一不能被当作第二个价格。原金额、原文证据位置保持不变，不删除真正的第二个金额。

## 实际旧回答回放

结果：`analysis/semantic_r4_offline_20261103`。

- 96次回答全部重验，r4下25/50通过程序门禁；其中17题仍含pending或uncertain。
- 与r3热修复后的28题相比，19764、20025、21120新增拦截，原因是报考/检修/故障背景被错误作为歧义待审。
- 在最终选用的有效回答中，6题移除了错误预算待审：3876、6893、7861、9286、11552、21576。
- 4题恢复了预算强弱：3723、12852、14894、21576。两组有重叠，不能相加当作修好10题。
- 11955在同一次原运行已有的第二答通过了新检查。选择已有另一条回答不等于产生了新的模型结果；`comparison.json`记录了来源行号变化。
- 真实的一米左右、异常一100包、两档包装AND/OR、店铺推荐等未决内容仍保留。

这些数字是程序如何处理旧回答的结果，不是新r4提示词的模型准确率。没有新请求，也没有足够依据扩大1000题。程序通过项仍须逐题核验对象、类别、属性和商品事实。
