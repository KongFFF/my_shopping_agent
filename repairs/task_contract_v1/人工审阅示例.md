# 人工审阅：先判语义，再决定如何修

下面是第一轮人工语义判读的示例，不是已应用的第二版修复。当前893题清单保持不变。完整107题证据卡见 [review_cards.md](review_cards.md)。

## 四步

1. **遮住标准答案，先读用户原文**：列出用户实际要求的品类、型号、规格、数量、预算；区分总价/单价、上限/下限，以及硬要求/近似偏好。不知道的就写“不确定”，不要从gold反推用户要求。
2. **核对商品证据**：目标商品和规格是否存在？所选完整SKU能否唯一确定价格？商品能否满足上一步列出的要求？只用当前冻结快照，不能拿现在网页的价格替换历史价格。
3. **定位责任**：原文明白但程序理解错→修通用规则；标注字符损坏且唯一可还原→修标注；目标确实违背需求→隔离并寻找重标注证据；价格本身缺失→补原始证据或隔离。
4. **记录并验证**：每次结论附一段原文和一条商品证据。可批量实施的结论写成通用规则，附正例和反例；重新跑整个训练集的审计，不只检查这一题能否满分。

## 审阅输出长什么样

例如6901：

```text
结论：规则可修
用户原文：“价格在50元以上”
商品证据：C款55元；A/B款47元
根因：价格下限被当作上限
拟采用通用规则：识别“以上/不低于”的下限，并执行下限校验
反例要求：不能只把price_upper改成None，从而让47元也通过
状态：规则与回归测试尚未实施，清单暂未变更
```

这类语义判断可以先由助手完成初稿，人工重点复核统一规则、确实矛盾的标注和无法补证的价格。无需让你逐行阅读JSON，也不需要凭主观判断补商品价格。
