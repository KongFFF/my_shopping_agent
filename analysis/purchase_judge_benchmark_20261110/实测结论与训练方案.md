# 历史购买自动核验：实测结论与训练方案

测试模型：`DeepSeek-V4-Flash-0731-W8A8`，学校网关，最大4个请求并发。仅本地CPU与API，无GPU训练。全部88种购买均已尝试；87/88种得到可用回答。`benchmark_execution_complete`表示测试已执行完，`responses_complete`/原报告`complete`表示是否每项都得到有效回答。两者不同；失败项本身也是验收结果，不无限重试。

## 结论

当前决定：`reject_current_online_judge; offline_diagnostic_only`。本轮候选存在明确的语义误放行，不接入真实GRPO评分，不重训，也不把API回答自动签收为商品事实。原1000题、981题试跑放行/19题整组暂缓、训练奖励公式和模型输入保持。

## 准确性

模型输出前，助手阅读冻结商品资料和所选规格，建立31个新购买组合的244项参考判断：166项满足、72项未知、6项明确不符；另有4组排序/等价检查。参考没有进入请求。它是定向分层审阅、包含同题相关判断，不是随机独立样本，不可外推为1000题准确率，且明确反例不足以估计罕见漏判率。

| 指标 | 实测 |
|---|---:|
| 已完成的参考项 | 244/244 |
| 原规则与参考一致率 | 45.5% |
| 单独LLM与参考一致率 | 88.1% |
| 规则优先、只补unknown后的参考一致率 | 87.7% |
| 原规则unknown子集上的LLM一致率 | 85.8% |
| 参考非pass却被LLM判pass | 25项 |
| 其中会进入混合奖励的误放行 | 25项 |

误放行计数表示与预先保守审阅口径不一致，不把每个细微同义争议都称为确定事实错误。不过任务243四档套餐被判为五档、天然被当作无添加、彩色外观被当作彩灯、可视被当作自带屏幕等，已足以表明仅校验引用存在不够。近似数值2.92米按2.9米通过，也违反已确认“仅精确目标/明示区间通过，其余未知”的规则。

逐项证据、原判断及模型判断见`independent_disagreements.jsonl`。4组排序结果见`school_flash_v1/ranking_comparison.jsonl`；不能因为新评分产生了更多非同分组就视为正确学习信号。

## 耗时和缓存

- 正式请求尝试93次，另有2次API可用性探测。错误统计：`{"ValueError: Evidence must exactly match an allowed selected-SKU public scalar": 3, "TimeoutError: timed out": 3}`。失败没有被包装成未知或有效奖励；全部历史尝试留在日志中。
- 正式请求已返回的用量合计为205407 tokens；另有探测用量，超时请求可能没有返回用量，不能据此精确核算计费或学校额度扣减。本轮没有租GPU。
- 唯一未得到有效回答的是旧准备部分的20753：共尝试4次，3次证据校验失败、1次超时；已停止重试。最新47种购买和全部244项参考均已得到判断，不影响上述独立语义样本的一致率。旧部分含该失败购买的两组仍保持`judge_unavailable`，不回退旧分。
- 成功请求含重试总耗时：均值16.45秒，P95 46.08秒，最大88.97秒。
- 新任务按历史生成批次回放、包含失败观察的整批等待：均值25.40秒，P95 56.31秒，最大56.31秒。重复输入先合并并共享等待；没有把同批尚未完成的future算成已就绪缓存命中。
- 旧两轮有41种独立需求/SKU组合；对新一轮125次购买的提前缓存命中为0，连商品本身的交集也是0。不能据此承诺提前缓存会覆盖后续多数任务。
- 新一轮125次购买仅47种组合：批内/跨批去重有价值，但同批重复轨迹仍须等那一次真实调用。最乐观逐条顺序计数的78次命中包含这种重复，不代表78条都无需等待。
- 旧v5两次实际更新记录的step耗时为[67.18857692554593, 66.12653841078281]秒、gen计时为[13.896121356636286, 13.09973880648613]秒。只是量级对照：gen计时可能没覆盖全部补采，且本地到学校网关的网络不同于AutoDL；本轮没有测GPU空转或异步重叠，不能据这些数精确计算租卡涨幅。

## 训练方案选择

1. **当前不采用“训练期间由这个LLM自由输出pass/fail，再直接更新”的方案**。语义误放行已构成阻断；超时和批次等待还带来额外成本。人工不进入租卡期间的同步链路。
2. **下一阶段选择离线辅助核验、程序计算奖励的路线**。LLM结果只作候选，优先让数量、套餐成员、量纲、近似数值等落成可核对的实际值和作用域，由程序比较；不能只检查“证据原文确实存在”。定性推断仍须独立审计，不自动把本轮回答写入已审事实缓存。这是后续实现方向，本轮未修改正式核验器。
3. **当前不启动快速奖励模型训练或正式GRPO**。88种购买和当前候选误差不足以证明可蒸馏出可靠模型；也不能承诺全1000题覆盖。后续先用另一批未参与修改的保存购买验收，再决定是否值得接自动在线服务或训练快速模型。
4. **采样多样性须独立处理**。旧v5的24个同分组中21组购买结果完全相同，补核验不能凭空制造分差。固定轨迹重评分不是新模型训练，不能证明SFT→GRPO能力差值增大。

这一选择不等于离线缓存已覆盖1000题，更不保证后续未见商品不需要核验。真正恢复训练，仍须具备可靠且足够快的运行时核验，或另行明确调整奖励覆盖范围；本轮没有擅自缩小任务集或改目标。

还发现一个规则侧的通用表示问题：7764的S码被规则判为不符合“小码”，LLM反而正确。规则优先并非“规则永远正确”；本轮保留它以忠实比较现有混合方案，未在看到结果后修规则重算以提高验收分。下一轮应集中修通用尺码同义表示，并用独立样本再验。
