# “加个/配个/有个”省略数词的gold核对

2026-11-06。检索完整题库23421条，原始query含任一字符串的有142题，其中原始GRPO训练1000题命中10题。加个11题、配个76题、有个56题，类别可交叉。字符串命中包含“有个性”“适配个人”等非目标情况，不能把142当作142条省略数词的数量需求。

## 结论

对象为具体、可数、独立的目标商品或配件，且无复数、集合、分配语境时，省略“一”可以按默认单数理解。但gold支持的是这类默认解释，不支持所有匹配强制总数量eq1。必须区别用户意图单数、商品整包数量、组件存在与恰好一件的排他限制。

## 非数量用法与标注缺陷

- 9825“我手头有个2230的NVMe固态”：用户已有物品，不是要求购买1块固态。
- 22051“听说有个六联苗”：存在性提及；实际需求和gold为一盒10瓶，不能补购药数量1瓶。
- 1307“大小有个一米二高”、6295“有个3米长”：约量用法，保留高度/长度，不提取数量1个。
- 3074“有个性化风格”、3331“适配个人电脑”：字符串子串命中，不是省略“一”。
- 22347“再加个大肠杆菌”：补充疫苗预防对象，不能变成购买1个细菌。
- 15693原文“再配个彩虹汉诺塔”，gold却是“磁力积木魔方+24段魔尺”，而商品另有汉诺塔套餐；属于gold组件不匹配，应复核，不应让gold覆盖原文。

## 建议的语义处理

1. 具体可数、单独指代且语境一致的“配个X/加个X”：可归一为默认1个X，证据仍逐字引用原文“配个X/加个X”，不能将证据伪造为“配一个X”。
2. 组件应绑定组件对象，不能误变成主商品或整单的购买数量。开放式附带要求优先验证包含/存在；除非有“只要、仅、恰好、不要多”等限制，不把多送一件自动判失败。
3. 套餐、一对、集体名词、多个安装位置、买赠语境优先保留其集合和分配关系；明确有其他数量时保留原数量。
4. “有个X”先辨识它是目标需求、已有背景、存在性提及、部件还是约量表达，再决定是否提取组件数量或仅存在要求。
5. 若schema只能用eq表达quantity，需明确这是默认请求数量，不应未经政策定义就用它拒绝包含更多同类配件的SKU；无法无损表达的集合/分配关系应进入待审。

本次仅分析，不修改提取器、schema、评分器或任何运行中的采集。
