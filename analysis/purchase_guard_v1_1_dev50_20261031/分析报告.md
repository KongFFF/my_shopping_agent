# v1.1 Dev-50：SFT 与已有 GRPO step500 的逐题分析

日期：2026-10-31。输入为本目录两套轨迹、摘要和 evaluation_spec。训练数据仍为原始1000题，未使用928题和v2评分修复。本次只做CPU离线诊断，没有训练、推理或Final评测。

**结论：当前RL出现了个别有效的搜索和规格行为改善，但尚未转化为广泛、稳定的端到端提升。共同失败同时包含候选利用不足、明确的规格/预算决策错误、工具参数错误，以及评分契约疑点。现有证据支持小规模验证采样与学习机制，不支持直接完整重训，也不足以认定粗粒度终局信用分配就是核心瓶颈。**

## 1. 证据核验与口径

- 6个输入文件逐字节SHA-256通过；两组各50条唯一任务，任务和协议相同。
- 从轨迹重新计算两份摘要，与保存的全部统计字段精确一致。
- 原始评分纯函数复算93次实际购买，奖励类型和数值全部匹配。
- 10次本地动作守卫拒绝全部复算一致：SFT4次、GRPO6次。
- 197次已执行规格选择（SFT97、GRPO100）均在环境 selected_options 中体现，未发现这类选择静默不执行。
- 其余终局为5次循环、2次缺规格重试耗尽；后者没有实际购买，不能算在93次购买复算中。
- 原商品库解压字节哈希与运行清单相同。隐藏目标、标注和规格枚举仅用于本次离线诊断，不进入策略输入。

当前比较的是“旧环境训练的SFT/GRPO模型，在同一v1.1环境部署”。它不是在v1.1下重新训练普通GRPO与改进GRPO的算法消融。单次Dev小样本不能证明稳定的泛化增益；没有读取Final。

## 2. 总体结果

| 指标 | SFT | GRPO step500 |
| --- | ---: | ---: |
| 严格成功 | 27/50 | 28/50 |
| 平均终局奖励 | 0.430100 | 0.449174 |
| 平均执行步数 | 8.76 | 9.12 |
| 部分满足购买 | 17 | 15 |
| wrong_purchase（包括未实际购买的重试耗尽） | 4 | 4 |
| 循环终止 | 2 | 3 |
| 无效奖励 / 执行异常 / 释放异常 | 0 / 0 / 0 | 0 / 0 / 0 |

配对结果：共同成功26、仅GRPO成功2（5293、7086）、仅SFT成功1（14141）、共同失败21。26/50题的已执行动作序列完全相同；相同序列计数不包含被拒绝的模型调用，不代表所有隐藏状态相同。

成功净增1题，平均奖励增加0.019073，平均步数增加0.36（约4.1%）。因此当前表现是小幅收益，整体执行效率未改善。

## 3. 三道成败发生变化的任务

### 5293：新增gold主要来自补点单值元数据项

用户要成年犬肠胃处方粮，重量不超过5斤、270元以内。两模型都买同一个商品、食品口味选“犬肠道2kg”、价格267元。GRPO相较SFT只多了一次 `select_option(value="0lb")`，选中净含量轴唯一值。

SFT为partial、奖励0.146875；GRPO为gold、奖励1。两者已执行动作前8步完全相同，随后SFT购买、GRPO补点0lb后购买。这是很清楚的局部协议完整性差异，但0lb是异常/疑似占位元数据标签，不能据此宣称GRPO更懂真实重量或营养需求。原正式评分保持不变，该题仍按既定gold计数。

### 7086：可解释为更好的继续搜索与候选选择

用户要面向鱼苗/泥鳅/虾塘的360度小型风送投料机，预算1500元左右。

两模型前7步相同：打开737433902654、查看信息并选“23升风机370w（可输送8米）”。SFT直接购买480元候选，得到partial=-0.3。GRPO返回搜索，改查“小型风送投料机 喂鱼苗”，目标商品首次出现在这次新结果中，随后打开913002863772，选择“360度小型风送投料机（不含管道）”，1530元、gold=1。

该题表明GRPO在本次运行中出现了实质的候选探索改善，而不仅是补齐格式。代价为8步增加到14步。单题轨迹支持行为差异，不能把它外推为搜索能力的稳定全面提升。

### 14141：候选选择、工具混用与循环共同造成退化

用户要军绿色、医用超声波、实时成像洁牙设备，口语预算“三百五上下”。原评分器未解析出此预算（price_upper=null）；本次仍保留原口径。

SFT在第7步打开934034097808，选军绿色、357元并正常购买。GRPO的搜索结果中出现过该商品，却始终未打开；它在其他三个商品间往返，三次调用 `select_option(value="buy now")`，均被正确拒绝，最终在16个执行步后因无进展循环终止。

SFT本题也有一次同类工具混用，但随后恢复并完成。因此不能说GRPO新引入了这种错误；更准确的是本次GRPO重复犯错且未恢复。增加重试或统一步数惩罚不能直接教会它选择正确候选及调用正确工具。

## 4. 共同失败21题：不能全部归为规格选择

以下“目标”指原评分器的标注目标商品；“出现”依据实际模型可见的投影后observation，“打开”依据实际执行动作。它们是事后定位指标，不是算法可使用的oracle信号。

| GRPO中目标到达情况 | 数量 | 任务ID |
| --- | ---: | --- |
| 已打开 | 9 | 3485、7061、8666、10077、12066、12703、14156、14929、16252 |
| 出现过、未打开 | 7 | 565、1220、9316、16272、17848、19606、20134 |
| 未出现在实际可见轨迹 | 5 | 652、8107、13399、16263、23126 |

12/21题没有打开目标，既可能是检索不足、结果排序/选择不足，也可能是过早接受当前候选。未打开不等于目标从未出现；出现目标也不等于模型能从现有信息唯一识别它。652还存在原评分契约下目标不可得gold的问题，不能直接算成可恢复的搜索损失。

已打开的9题可进一步分开：

| 类型 | 任务 | 直接证据 |
| --- | --- | --- |
| 明确需求与规格/预算未绑定 | 3485 | 要标准款，选“米白色”而非页面上的“米白色常规” |
| 明确需求与规格/预算未绑定 | 10077 | 要两片扁插头，页面有2脚3米，选成3脚3米；预算70元也未被原评分器解析 |
| 明确需求与规格/预算未绑定 | 12066 | 要≤250元；选299元规格后换276元，仍购买，页面另有可得gold的S10 |
| 明确需求与规格/预算未绑定 | 14156 | 明确宽松鞋型，选普通“海豚黑”而非“海豚黑（宽版）” |
| 隐藏/格式规格要求混入 | 7061 | 目标要求“下单勿使用号码保护”等轴；定金、补拍、全款语义也混杂，不能当纯能力错 |
| 隐藏/格式规格要求混入 | 8666 | 已选买10送1，但未点单值“颜色分类=规格”而丢gold |
| 隐藏/格式规格要求混入 | 12703 | 尺寸和改短均满足，选挂钩；用户未要求打孔，隐藏标注强制打孔 |
| 原预算契约导致目标不可得gold | 14929 | 用户20块左右，目标唯一规格22元，原规则上限20元 |
| 工具参数复制失败 | 16252 | GRPO尝试4包分体正确方向，但省略空格和末尾右括号，三次被守卫拒绝，随后重试耗尽 |

15道共同partial中，14道规格维度不满分、9道核心功能不满分，这些计数重叠。购买了错误商品时目标规格在该商品本来就不存在，因此14/15绝不能解释为14道只需改最后一次规格选择。

## 5. 一个会掩盖真实改善的评分例子：8666

用户明确要单边拉链压脚“买10送1”、100元内。两模型都打开目标商品：

| 项目 | SFT | GRPO |
| --- | --- | --- |
| 实际套餐 | 隐形单边拉链压脚1个 | 单边拉链压脚买10送1 |
| 价格 | 9元 | 90元 |
| 单值元数据“颜色分类=规格” | 已选择 | 未选择 |
| key_options得分 | 0.5 | 0.5 |
| 最终奖励 | 0.186538 | 0.186538 |

GRPO在数量套餐上更符合用户需求，但评分器对“数量套餐”与“规格占位项”分别算一个规格要求，导致两条不同质量的结果同分。这里的问题不是“终局反馈出现得太晚”，而是该比较的奖励排序没有体现用户重视的区别。局部分叉若得到同样一对同分结局，仍不能凭空产生区分信号。

这不是要求现在重新清洗数据或更换用户指定的原1000题。正式分母、评分和数据都不改；本次只把指标口径和语义疑点标清，不把占位项收益直接宣传为需求理解提升。

## 6. 反事实与研究范围

对实际已买商品枚举全部原规格（含不选），在原评分器下GRPO有7道失败存在同商品gold组合：3485、7061、8666、10077、12066、12703、14156。枚举没有超出10000组合上限。

其中7061、8666、12703带上述标注/占位疑点，不能将7道全当成干净、明确的能力错误；更清楚的局部研究例子为3485、10077、12066、14156。这个数字是使用隐藏标注得到的离线上界，不是预期新增成功数，更不能承诺Final增加多少百分点。

另外，652、14929在原预算/商品契约下穷举目标规格也无gold。按当前定义只有目标身份才能是gold，其他商品至多valid_alternative，因此不能用增加探索承诺消除这两题的严格失败。

## 7. 对下一步的建议

1. 暂缓完整重训，不根据本次Dev反复改模型或再次读Final。把v1.1、原1000题和这次27/50基线固定为后续共同条件。
2. 下一笔GPU预算先用于训练集的小规模采样诊断，暂不更新参数。预先选20–30道原训练任务，覆盖候选选择、复合规格、预算、工具参数等情况；不用这些Dev ID设计分叉或向策略提供目标商品。
3. 在SFT正常产生的状态下，比较普通整轨迹采样与同历史/同环境状态的后缀分叉。记录关键动作是否改变、是否得到有效奖励差异、是否出现更符合公开需求的选择，以及重放/prefill/生成成本。仅比较几条同长度后缀的最好结果不能证明端到端训练有效。
4. 若仅在已经到达合适商品后分叉，研究范围就定位为候选利用/规格购买决策；不能声称覆盖这21道失败中的主要搜索问题。后缀允许返回搜索时，需要连同额外环境与生成成本测量。
5. 有效奖励比较能稳定产生后，再用小预算普通GRPO与改进GRPO对照，最终衡量同预算下相对SFT的单次成功率净增。增加有效组数、best-of-k提高或少点占位项都不是训练后pass@1改善的替代指标。

当前仍不能证明终局信用分配、探索不足或更新预算中任何一个是主因。新证据更支持把“有效候选的利用、关键约束到规格的绑定、正确工具执行及奖励能否区分真实改善”联合检查，而非直接把所有失败归因于终局奖励粗。

## 8. 复现与逐题产物

从父仓库运行：

```bash
python tools/analyze_guard_dev50.py
```

脚本只用Python标准库与上游纯函数，不启动服务或加载模型。输出：

- `derived/evidence.json`：完整性、奖励/守卫复算和各类计数。
- `derived/paired_tasks.csv`：全50题的结果、步数与目标到达对照。
- `derived/case_reviews.json`：全100条轨迹的紧凑审阅记录，含比较器证据、动作、原规格、拒绝记录及标为oracle-only的反事实。

原始6文件和清单只读保留；Windows分析文件的LF换行规则已补充，防止哈希受自动CRLF转换影响。本次分析没有修改训练实现、任务分母或评分器。
