## 8666：两类规格混为等权要求

公开需求为工业电脑平车、全钢、单边隐形拉链压脚，买10送1、100元内。目标商品实际包含两个选项轴：

- T168：`隐形单边拉链压脚1个`（9元）、`单边拉链压脚买10送1`（90元）。它决定实际套餐。
- 颜色分类：只有`规格`。这是实际页面元数据，不是模型编造；该词不表示颜色、数量或用户明确要求的属性。

评分器把 instruction_options 中两个标注值都转换成required_options_by_key，在key_options内部按通过轴数/要求轴数算分。两个要求同权。因此“套餐错+点规格”和“套餐对+漏点规格”都得0.5。

进一步核对发现，expected_model被提取为纯数字`10`。提取器允许纯数字，只要同时出现在需求与目标商品标题中即可；商品标题含买10送1，所以选1个也通过model维度。数量语义被错误当成型号，并以商品级标题而非实际SKU计分。

本题active维度为core_functions=0.25、model=0.25、key_options=0.15，两模型前两项都满分：

```text
match_score = (0.25×1 + 0.25×1 + 0.15×0.5) / 0.65
            = 0.8846153846
partial_reward = -0.30 + 0.55×match_score
               = 0.1865384615
```

原评分纯函数枚举复算：

| 实际套餐 | 是否点“规格” | 当前奖励 |
| --- | --- | ---: |
| 1个 | 否 | 0.1230769231 |
| 1个 | 是 | 0.1865384615 |
| 买10送1 | 否 | 0.1865384615 |
| 买10送1 | 是 | 1.0 |

后两行真实套餐相同，补点无区分含义的元数据却触发大幅跳分。中间两行用户需求满足度不同却同分。不能据此认定整套GRPO无学习信号，但该比较本身不能鼓励更正确的数量选择。

理想排序应先明确真实购买内容、数量/组成、实际总价，再核对公开需求。相同套餐不应因无实质含义的占位项产生能力分巨大差异；套餐/数量不符合明确需求时，应低于符合者。具体奖励数值和是否对缺数量施加硬门控尚未敲定。单值轴并不一律可忽略：例如用户明确要求黑色，而商品只有黑色，这仍是有意义的属性；识别占位不能仅用“只有一个值”。若购买协议需要选择单值项，应默认补全或明确提示，将可执行完整性与语义质量分开处理。

## 套餐之外的已确认问题与候选风险

1. **非套餐占位要求**：5293两模型商品、犬肠道2kg与267元价格相同，补点0lb即从0.146875变1。这反映评分把异常单值净含量标签当成重要要求。
2. **公开需求未指定却被标注强制指定**：12703没有要求挂钩/打孔，原评分强制打孔；挂钩且尺寸、改短等均满足仍被扣规格分。不能把原gold的偏好反推为用户必须偏好。
3. **预算自然语言与评分规则不一致**：14929的20块左右被判上限20，唯一目标规格22元，目标没有可得gold组合；652的500块左右同类。此为已确认的契约问题，未在本次更改原规则，不能把它直接等同于已观察到一对轨迹的排序反转。
4. **数量/年份等进入型号维度**：8666的10已确认语义来源不当。原训练中63题expected_model含纯数字，Dev2题。63是审阅候选，不是63道错误，因为数字也可能是真实型号。
5. **部分奖励与严格成功不同**：23126的GRPO最终买了“没有填充物”的枕套，奖励却高于SFT另一种有草本填充但形态/颜色不符的商品。两者满足不同要求，尚不能在未明确偏好权重时断言严格谁更好，因此仅列为待审的排序样例，不纳入已确认错误数。

需要区分：已复现的同分/错误区分、明确的评分契约冲突、以及需要更多语义判断的候选。不能把所有低分或失败都当成奖励函数有错。
