# semantic evidence pilot v3：真实采样审计

依据：`training_diagnostics.jsonl`，2026-11-09同步，仓库提交`6c7431c`。本报告只分析本次训练采样；不是Dev、Final-clean或独立模型评测。本次未启动额外训练、未调用LLM API、未改变冻结奖励或原1000题。

## 结论

本次完成1次优化器更新，之后连续3轮各只得到1组合格组而停止。停止保护按配置工作。当前不能通过提高停止阈值就认定可以扩大训练。

有两个同时存在的问题：

1. **重复购买导致合理同分。** 18个同分组中15组购买相同商品和规格，修复商品核验也不会凭空产生购买结果的比较信号。
2. **商品事实覆盖不足，且有通用核验错误。** 3个同分组购买结果不同，其中11205、15910丢失了值得核验的需求差异；14950的颜色差异本身不在需求中，不应为了非同分而强行区分。同时，实际参与更新的9199组存在颜色误判及体重事实作用域不一致，说明数值不同时也可能提供错误的比较方向。

需求侧1000题的结构化和放行，不等于商品侧已能充分核验真实采样。此次试跑的30个购买商品，没有一个命中19个商品的离线审阅事实缓存；运行时主要依赖现有自动提取规则。

## 已查实的通用问题

### 1. 颜色子串提取破坏原始色名

- 9199需要粉色，所选“粉红色”被规则抽为“红色”，因而判fail；“粉色背心”被抽为粉色并判pass。
- 该组新奖励因此为粉色背心−0.09375、粉红色护肚服−0.1625。该组已参与第一次参数更新。
- 22458要求天蓝色，所选也明确为天蓝色，但被抽为蓝色，核验变成unknown。
- 原因是颜色词表未覆盖完整色名，短词“红色/蓝色”被当成完整、互斥事实。
- 建议先保留完整色名，处理经确认的别名/包含关系；复杂颜色描述不能靠命中短子串直接给fail。修复后仍需综合功能、体重适配判断9199，不能只凭颜色宣布哪件商品整体更好。

### 2. 适配对象作用域不一致

- 9199所选“XS胸30背20 约1-2斤左右”已被自动规则提取出1～2斤区间。
- 事实subject却是`primary_product/主商品`，需求subject是`intended_user/小型犬`；精确键匹配找不到事实，最终unknown。
- 建议把穿戴者适配事实绑定到明确的使用者角色，在比较器做受限角色对应；不能直接删除subject匹配，否则会混淆附件、主商品及使用者的尺寸。

### 3. 尺寸文本不一致被错误判为真实不满足

- 14950原文要求“1.5*2米”，所选尺寸“1500mm*2000mm”。
- 当前按完整字符串相等判断，输出fail，没有识别单位等价。
- 需要支持有明确单位、保持顺序的规格规范化；若继续采用只认同一完整标签的保守政策，至少应保持unknown，不能仅因文本不同判fail。不能擅自交换长宽轴或将裸“寸”换算成英寸。
- 此题颜色没有要求；修正尺寸后两个颜色SKU仍可能合理同分。

### 4. 公开资料存在，但尚未变成可比较事实

- 11205的公开属性明确有“人声、便携式、和声、民谣弹唱”，但相关项大多仍unknown；套餐标签中的赠品差异也未被核验。
- 15910所选SKU明确写“四代带堵头”，但代次、堵头等仍unknown；裸“1寸2”与要求“1.2英寸”的换算不应擅自等同。
- 21787的所选SKU为“熊猫炼乳350g*1罐”，规则未提取净含量/罐数；公开属性中的“加糖、烘焙、奶茶、咖啡、甜品”等也未被对应核验。数量单位、每罐与总量须保持明确。
- 建议采用可复用的结构化SKU规则和离线商品事实提取，沿用公开证据与SKU作用域约束，不把原目标ASIN、目标选项或未选SKU当成事实。

## 接下来工作的边界

1. 先修通用比较错误：完整色名、适配对象、尺寸规格的保守比较、明确包装数量/净含量。保留原需求、原商品与冻结v1诊断。
2. 从本次30个商品、35个题目与SKU组合开始补公开商品事实，用已保存的96条轨迹离线重评分，审查9199排序、11205/15910差异及未知比例。该队列只缩小调试范围，不构成全训练池覆盖验收。
3. 单独处理采样多样性：15组同SKU的情况不会因补事实自动变成非同分。修复奖励后再比较采样配置、困难任务或分叉采样；不为了凑组而对等价结果随意加分。
4. 通过离线排序验收后，重新冻结奖励与商品事实，再恢复小预算试跑。不要用这一轮1次更新的参数继续正式训练，也不要把它与原GRPO500当成同等预算实验比较。

此次只完成诊断和后续商品事实审阅队列，没有修改奖励运行时，也没有声称已解决上述问题。
