# 批次验收与训练放行（2026-11-08）

已完成本批验收，放行**最多20个优化器更新步的小预算GRPO试跑**。原1000题、原query、原训练/验证parquet保留；981题可以使用新奖励参与更新，19题整组不可评分。本轮没有启动训练，没有调用LLM API，也没有运行Final-clean。

## 2. 批次签收依据

本批采用“此前审阅结论＋全量程序检查＋固定抽样复核”，明确区分批次接受与逐题人工整题签收。未根据`program_valid=true`直接把全部题标成已人工审批，也没有重新调用LLM提取。

- 固定抽样60题：40题按固定hash均匀选取，20题按组合数量、近似值、对象等风险选取；先固定名单，再查看商品评分结果。
- 对60题逐题阅读原query与全部结构化需求。45题未发现本轮需修改项；12题明确修订后复核；3题按源限制暂缓。
- 同类定向检查后，共38题结构化字段发生语义/属性修订。它不等于38道原始任务都不可用，也不含仅改变review_status的记录数。
- 981题经批次接受后通过`require_reviewed=True`严格验证；所有1000题通过基础结构、原文证据、类型和单位检查。19题仍保持独立hold登记。

明确修正包括：可添加果粒是设备能力，不是随货果粒；正品是成色/商品状态，不是品牌；补回009琴弦规格与喷杆可调长度；将层数、颜色数、像素数、孔数分开，避免泛化count槽互相支持；倍数浓缩/变焦及酒精度不再作为物品件数；去掉重复的轻薄、富晒和订金字段；“温润”归到白玉髓；同色马甲/长裤绑定原文明示的黑色。

16481按用户最新裁定保留**一套灰色、一套黑色**的关系，不能只买任一颜色，也不能用“灰黑拼色”自动通过。当前商品没有该分配关系的证据时仍为未知，不因源标签签收就凭空满足。

抽样发现错误后已修正，但这60题包含风险抽样和已修题，不构成“全1000题零错误”的统计证明。允许的是受限试跑，不据此无限扩展训练预算。

## 4. 训练入口与预算门槛

新增的批次凭据绑定原query、修订前后合同、抽样审阅、源限制、历史回放和相关文件哈希；运行时同时冻结代码、政策、事实缓存、原数据及作用域凭据。更改这些内容会导致预检失败，需要重新验收/冻结。

批次签收不覆盖既有整题签收标志：原7题的精确证明保持；其他已接受题通过独立的batch acceptance凭据放行。`formal_training_ready=false`与`pilot_training_ready=true`分别表示“未放行完整正式训练”和“已允许受限试跑”，不是互相矛盾。

命令入口、加载模型前的运行时预检及worker后端都检查试跑限制：

- `trainer.total_training_steps`为1～20的整数；不允许500步。
- `trainer.resume_mode=disable`，避免接入旧训练状态。
- `data.train_batch_size=2`，`actor_rollout_ref.rollout.n=4`。
- 动态采样开启，`max_num_gen_batches=3`，连续跳过更新达到3次则终止。
- 训练/验证parquet必须与冻结的原文件相同；验证继续单独报告原生v3指标。

“20步”限制优化器更新数，不等同于固定墙钟或固定轨迹数。补采和跳步仍会消耗生成成本。建议关闭试跑前及周期性的Dev验证，先看训练链路与采样信号。

测试结果：132项既有语义/奖励回归、32项CPU训练入口与批次放行测试，共**164项通过**。CPU测试中生成和HTTP响应为脚本化输入，奖励后端、adapter与动态采样筛选为真实实现；没有声称已通过GPU训练验证。

额外核对了固定版本的构造参数：veRL0.8先用`DictConfigWrap`包装trainer配置，再由基类存入`self.config`；worker预算检查因此读取已解包的配置，并补充了构造路径回归测试。[veRL v0.8.0上游实现](https://github.com/volcengine/verl/blob/v0.8.0/verl/experimental/agent_loop/agent_loop.py)
