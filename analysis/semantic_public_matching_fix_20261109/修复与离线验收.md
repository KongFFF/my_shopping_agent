# 商品核验通用修复与离线验收

日期：2026-11-09。依据是用户同步的`semantic_evidence_pilot20_v3`真实采样。本次修复商品核验实现，未修改原1000题、结构化需求、奖励区间/权重、19题整组不可评分政策，也未启动GPU训练或调用LLM API。

## 修复位置

实际流程仍为：原始query → 模型购物 → 实际购买商品与所选规格 → 结构化需求逐项核验 → 既定奖励公式 → GRPO组内比较。本次修复位于“实际商品与所选规格 → 逐项核验”。

新增`tools/semantic_public_matching.py`，由当前商品核验器调用，版本标识为`semantic-product-verifier-v4-public-matching-r2`：

- 保留完整颜色名，粉红色不再截成红色，天蓝色不再截成蓝色；粉色/粉红色按常用同义色名匹配，细分色不擅自合并。
- 所选尺码中的穿戴者身高/体重事实，可对应需求的明确`intended_user`角色；不取消其他对象/附件作用域约束。
- 明确公制单位的有序尺寸可规范化比较，例如1.5×2米对应1500mm×2000mm；不交换尺寸顺序、不猜尺寸轴、不换算裸“寸”。原`matches_label`政策仍只接受同一规格标签。
- 恢复对公开属性、标题/描述及所选SKU的明确文字匹配，支持少量语法外壳和已确认同义词；例如“带有和声功能”对应“和声”，“能够用于民谣弹唱”对应“民谣弹唱”。
- 补明确包装数量与单容器净含量，如“350g*1罐”“1号_10个装”；数量变体存在时，未选SKU或通用标题中的数量不能借给当前购买。
- 通用赠品要求仅核对当前所选SKU的明确赠品声明，不捏造赠品名称、件数或“电池套餐一定无赠品”。
- 额外堵住“配件齐全”的通用属性回退：存在套餐选择时，单机不能因为公共属性写了配件齐全就通过。

保留限制：否定、冲突、可选/另购信息不能直接变成满足；容量/接口数量不能变成购买件数；兼容品牌列表不能当制造品牌。没有公开证据的项仍为未知。

## 当前结论

已完成这批通用核验问题的实现修复、历史回归和真实采样离线验收，并接入当前训练后端。仍有449项未知，16组仍同分，其中15组本来就买了相同SKU。现在不能保证恢复原来的3批采样预算就能顺利跑完20次更新，更不能据此放行500步正式训练。

下一步应检查剩余未知中可由公开商品事实解决的高频类型，并单独评估采样多样性。不要为了凑齐合格组给相同或等价购买添加任意分差。
