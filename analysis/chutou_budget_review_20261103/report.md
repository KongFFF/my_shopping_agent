# “出头”预算表达：全量检索与定义建议

日期：2026-11-03。结论是新的分析建议，不是对既有政策的自动替换；未修改训练集、修复包或评分器。

## 范围与证据

- 原始 GRPO 训练集1000题：19题，全部列在 train19.md，含预算、价格、售价、元/块/块钱及省略单位的金额表达。
- 原始压缩商品题库23421条：565题含“出头”；17题仅描述体重、长度、克重等，排除后有548题涉及金额。
- 548题中459题的所有标注规格报价均可匹配且一致；89题不能直接确定报价（未匹配、轴价冲突、单位范围不一致等），不纳入价差和覆盖率分母。
- 训练19题中17题可确定报价；18115的报价1008/7999、21105的报价2080/2880互相冲突，不能沿用旧审计器取出的单轴价格作为整套SKU确定价格。
- 83号的规格标注含损坏问号，复用已有唯一装饰符恢复函数后，定位422元规格。
- 1421为4.3平方米总预算，而商品468元为每平方米价，单独排除直接比较，没有把468误当总价。
- 商品原始tag不等于GRPO训练1000集合；以data/grpo/train.jsonl中的ID集合为准。
- 所有价格均为本地数据快照中的标注规格报价，并非当前电商实时报价。报价可确定不表示商品满足所有非价格需求，也不表示整题gold一定正确。

可追溯文件：all_records.json保留原query、ASIN、原规格、匹配报价、修复前文字；all_questions.md为548题全表及17题非金额排除项；analyze.py可复算。

## 规则比较

覆盖仅指gold报价不超过规则的预算上限，不代表整题奖励通过。548题属于同一题库的描述性分析，不是独立泛化评测。没有根据这些价格改写任何评测答案。

|规则|训练明确报价17题|全题库一致报价459题|
|---|---:|---:|
|现行v2：两位+4、三位+9、四位+99…|16/17，94.1%|340/459，74.1%|
|统一增加10%|15/17，88.2%|376/459，81.9%|
|增加max(4元,10%×X)|17/17，100%|419/459，91.3%|
|增加max(4元,20%×X)|17/17，100%|449/459，97.8%|
|上述20%容差，再限制不跨下一金额档位（推荐）|17/17，100%|446/459，97.2%|
|增加max(4元,30%×X)|17/17，100%|458/459，99.8%|

训练17题全部略高于基准，增幅中位数5%，最高20%（10→12）。全题库一致报价459题中448题高于基准；这些正增幅的中位数5%，90分位18%，95分位20%。另有6题低于、5题等于基准，说明预算上限与售价区间不应混为一谈，且原始标注本身存在噪声。

## 推荐定义：小额保留绝对容差，大额使用比例容差

建议把“预算X元出头”定义为：预算以X元为基准，接受小幅上浮；默认上限

    T(X) = X + max(4元, 0.20 × X)
    U(X) = min(T(X), 下一金额档位 - 0.01元)

此处以人民币分为最小单位，且只讨论本数据中观察到的整数基准X≥10。金额档位由基准精度决定：X末尾连续零的个数为z，档位步长Q=max(10,10^z)，下一档为(floor(X/Q)+1)×Q。例如65的下一档70，420的下一档430，400的下一档500，1000的下一档2000。此精度规则只看query中的基准金额，不看gold价格。

这是一条面向本数据集、优先兼容口语表达的工程约定。选择20%是因为全题库正增幅的95分位约为20%，不是因为自然语言具有精确的20%数学边界；再用金额档位避免65→78、420→504等不合理扩张。更严格的10%版本也可用，但会排除40/459个报价。

- 10元出头：预算上限14元。
- 20元出头：预算上限24元。
- 65元出头：预算上限69.99元，即低于70元。
- 420元出头：预算上限429.99元，即低于430元。
- 100元出头：预算上限120元。
- 400元出头：预算上限480元，8784的419元可通过价格条件。
- 1000元出头：预算上限1200元。
- 2000元出头：预算上限2400元。

边界和组合：

1. “预算X出头”通常表达可花的钱，默认只检查P≤U，不强制买得比X贵。“售价X出头”若明确限定商品价格区间，按X<P≤U；低于/等于X的标注不能仅凭gold身份判定符合“略高于X”。
2. 有明确硬上限时取更严格者，例如“400出头，不能超过430”最终上限430。明确上下限继续保留。
3. “大概/左右/差不多X出头”不重复叠加容差；“最好”仍需保持偏好性质。
4. 单价、总价、数量和套餐范围必须先对齐；先确认完整SKU价格，再做比较。
5. 此次实证建议只覆盖数据观察到的金额范围，不给“5元出头”等未观察的小额或其他属性（体重、尺寸）自动套用同样规则。
6. 若用于严格表达“只多一点”，可以保留10%作为偏好目标，20%作为可接受外沿；此时应清楚区分偏好分与硬门槛，不再额外上浮。

## 与现有规则的关系

既有v2是此前记录的用户确定政策，不能把本报告的新建议称作已经批准的新标准。本次仅完成检索、报价核对和候选定义比较。采用本建议将改变许多预算边界，应作为后续版本的明确政策变更，统一应用，不能只为8784加特例。
