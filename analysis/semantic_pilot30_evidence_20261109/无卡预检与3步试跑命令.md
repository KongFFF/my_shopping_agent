# 无卡预检与3步试跑命令

本轮限定最多3次优化器更新，仍从原SFT step300出发，保留原1000题及19题整组无效政策。不是500步正式训练，也不是重复旧v3目录。先执行无卡步骤，再切换有卡；切换实例/模式后重新设置变量并检查环境服务。

## 1. AutoDL拉取与安装（无卡）

```bash
set +e
set +u
set +o pipefail
shopping_sync() {
  cd /root/autodl-tmp/work/my_shopping_agent || return
  git status --short || return
  git pull --ff-only origin main || return
  git submodule sync --recursive || return
  git -c 'url.https://github.com/.insteadOf=git@github.com:' submodule update --init --recursive || return
  export PROJECT="$PWD/upstream/shopping-grpo-longhorizon"
  export PY="$PROJECT/.venv/bin/python"
  test -x "$PY" || { printf 'Python不存在：%s\n' "$PY"; return 1; }
  "$PY" tools/install_evidence_training_runtime.py --apply --backup-existing || return
  "$PY" tools/install_evidence_training_runtime.py --check || return
  git log -1 --oneline
}
if shopping_sync; then
  printf '同步成功，继续第2步。\n'
else
  printf '同步失败，先检查上方输出；终端保留。\n'
fi
unset -f shopping_sync
```

只在本步骤成功后继续。子模块本地修改属于既有运行时安装结果，不向原作者仓库push。

```bash
"$PY" "$PROJECT/scripts/train_grpo.py" \
```

输出目录应为新目录；不要提前向其中写日志。若该目录已有运行记录，保留它，换一个新名称并重新dry-run。

## 4. 检查ShopSimulator和Ray（CPU操作，在实际有卡训练实例上执行）

切换有卡模式后，先重新执行第2步设置变量，再执行本步骤。此步骤不加载模型、不做训练，但环境服务必须与随后训练位于同一实例。

```bash
cd /root/autodl-tmp/work/my_shopping_agent
export SERVICE_DIR="$PROJECT/outputs/runs/semantic_evidence_pilot3_services"
mkdir -p "$SERVICE_DIR"
export SERVICE_LOG="$SERVICE_DIR/environment_$(date +%Y%m%d_%H%M%S).log"
if "$PY" - <<'PY_CHECK'
import socket
try:
    with socket.create_connection(('127.0.0.1',5700),timeout=2): pass
except OSError:
    raise SystemExit(1)
PY_CHECK
then
  printf '5700已监听，继续API检查。\n'
else
  nohup env PYTHONUNBUFFERED=1 PYTHONPATH= OMP_NUM_THREADS=1 \
    SHOPSIM_PORT=5700 SHOPSIM_ENV_SLOTS=8 SHOP_MAX_STEPS=35 \
    bash "$PROJECT/scripts/start_environment.sh" \
    > "$SERVICE_LOG" 2>&1 < /dev/null &
  printf '%s\n' "$!" > "$SERVICE_DIR/environment.pid"
fi

if "$PY" tools/probe_shopsim_service.py \
  --base-url http://127.0.0.1:5700 --wait-seconds 120 --slots 8
then
  "$PY" tools/probe_evidence_ray_worker.py \
    --manifest "$EVIDENCE_MANIFEST" --reward-tools-dir "$REWARD_TOOLS" \
    --env-url http://127.0.0.1:5700
else
  printf '环境API未通过，暂不启动训练。\n'
  if test -f "$SERVICE_LOG"; then tail -n 80 "$SERVICE_LOG"; fi
fi
```

须先看到服务探针通过，以及Ray输出`nested_ray_probe_passed:true`、`released_tasks:981`、`held_tasks:19`，再执行下一步。

## 5. 最多3次更新（必须有卡）

这是实际训练命令，去掉了`--dry-run`，从SFT权重开始，不续训此前只有1次更新的v3模型。

```bash
cd /root/autodl-tmp/work/my_shopping_agent
"$PY" -u "$PROJECT/scripts/train_grpo.py" \
  --model "$SFT_MODEL" --output "$PILOT_OUT" \
  --env-url http://127.0.0.1:5700 --logger console \
  --experiment-name semantic-evidence-pilot3-v4 \
  --evidence-reward-manifest "$EVIDENCE_MANIFEST" \
  --reward-tools-dir "$REWARD_TOOLS" -- \
  trainer.total_training_steps=3 trainer.resume_mode=disable \
  data.train_batch_size=2 actor_rollout_ref.rollout.n=4 \
  shopping_dynamic_sampling.enable=true \
  shopping_dynamic_sampling.max_num_gen_batches=3 \
  shopping_dynamic_sampling.max_consecutive_skipped_updates=3 \
  trainer.val_before_train=false trainer.test_freq=-1 trainer.save_freq=3
```

若再次触发连续3轮凑不齐组停止，保留日志，不提高保护阈值强行跑满。3次更新只是观察新奖励、loss/梯度、有效组与真实覆盖情况；不能承担模型能力提升结论。原20步的参与上限政策仍保留，本次主动采用更小预算。

## 6. 同步诊断（无卡即可）

在AutoDL仓库根目录，只同步本轮分析需要的轻量文件。若使用了不同输出名，修改`RUN`后再执行。

```bash
cd /root/autodl-tmp/work/my_shopping_agent
RUN=upstream/shopping-grpo-longhorizon/outputs/runs/semantic_evidence_pilot3_v4
DEST=analysis/semantic_evidence_pilot3_v4_results
mkdir -p "$DEST"
for name in training_diagnostics.jsonl launch_audit.json reward_manifest.json; do
  if test -f "$RUN/$name"; then cp "$RUN/$name" "$DEST/$name"; fi
done
git add -- "$DEST"
git commit -m "data: add semantic evidence pilot v4 diagnostics" -- "$DEST"
git push origin main
```
